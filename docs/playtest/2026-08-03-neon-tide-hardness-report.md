# Neon Tide · 玩家反馈转化报告

日期：2026-08-03  
来源：玩家直接试玩反馈  
样本：当前桌面/移动浏览器版本

## 1. 原始观察与解释分离

| 原始观察 | 解释假设 | 严重度 | 频率 |
| --- | --- | --- | --- |
| 难度太低 | 玩家没有被迫使用冲刺、路线选择和资源管理 | P0 | 全局体验 |
| 敌人速度太慢 | 追踪压力不足，玩家可在屏幕边缘无风险绕圈 | P0 | 全局体验 |
| 攻击方式太单一 | 敌人行为只要求“远离”，没有读预警、切线、穿越和反制差异 | P0 | 中后段尤甚 |
| 敌人数量太少 | 同屏威胁不构成空间决策，收集物与危险没有形成路线冲突 | P0 | 全局体验 |
| 每幕时间太短 | 阶段学习与掌握刚开始就切换，幕间奖励没有形成节奏 | P1 | 关卡节奏 |
| 画风粗糙不精致 | 原语轮廓、背景层次和材质细节不足，视觉语言没有达到“霓虹海战”承诺 | P1 | 全程 |

## 2. 优化前代码证据

- 当前阶段边界为 `0/18/38/53` 秒，首领前总时长 53 秒；第一幕只有 18 秒。
- 当前敌人基础速度约为追踪者 `1.05 + elapsed * 0.012`、突袭者 `1.25`、精英 `0.82`。
- 生成间隔下限约为 `0.38` 秒，但前两幕主要是单体生成，且导演预算受 24 个敌人上限限制。
- 常规敌人角色只有追踪、直线突袭、区域爆炸、精英追踪；没有持续封路、编队切线或远程预警攻击。
- 视觉主要由平面几何、圆环、网格和粒子组成；缺少可见材质层级、空间前后关系和战斗关键形状的精密细节。

## 3. 优先决策

### P0 · 战斗压力

1. 把关卡时序扩展为 `0/30/64/100` 秒，首领窗口 26 秒，总局约 126 秒。
2. 把常规敌人上限提升到桌面 36、粗指针设备 28；粒子和拖尾同步增加但仍有硬上限。
3. 让生成导演以编队/组合为单位，最少同时制造两条不同方向的威胁。
4. 将追踪者速度提升约 80–120%，但给所有新攻击保留 0.45–0.85 秒预警。

### P1 · 内容与视觉

1. 增加光束封路者、蜂群无人机和精英冲击波三种攻击语言。
2. Boss 进入二阶段后切换攻击池和视觉材质，不只增速。
3. 精修飞船、敌人、背景流体和 HUD 的层级、轮廓、内发光、局部细节。
4. 桌面端启用受控 Bloom，移动端降低 Bloom 强度和背景粒子数量。

## 4. 可验证成功指标

- 前 30 秒至少出现 3 种敌人行为、2 次编队生成和 1 次需要冲刺穿越的路线冲突。
- 30–64 秒同时存在追踪＋直线突袭/光束至少两类威胁；64–100 秒至少三类威胁组合。
- 首领前每 8 秒平均至少有一次组合事件，而不是单个敌人入场。
- 同屏敌人数达到桌面 18–30 的常态区间，移动设备维持 14–24 且不遮挡全部可行路线。
- 每幕至少 30 秒；阶段切换不在玩家刚理解新敌人时立刻发生。
- 所有高伤害行为都有形状、颜色、方向和时间进度四种可读信号。
- 桌面截图中可辨认飞船主体、翼面、核心、敌人角色差异和背景前后层；移动截图中仍保持主体轮廓和目标可见。
- 低帧率/移动端仍保持可玩，不通过无预警的瞬时伤害制造难度。

## 5. 后续验证问题

- 玩家是否会主动用冲刺穿过敌人，而不是一直逃跑？
- 编队是否形成“选路线”而不是“屏幕全红”？
- 新的光束/蜂群是否能在首眼识别，并且不与光核颜色混淆？
- 126 秒单局是否仍有重开动力？若没有，后续再加入短局模式而非继续压缩主线。

## 6. v2.1.0 实际落地结果

| 反馈 | 已交付变化 | 可验证结果 |
| --- | --- | --- |
| 难度太低、敌人太少 | 三幕改为 30/34/36 秒；桌面/粗指针敌人硬上限提升至 36/28；导演每 5–9 秒组织夹击、交叉火力、雷墙、螺旋和精英护航 | 阶段边界固定为 `0/30/64/100`，Boss 窗口 26 秒，总局 126 秒；导演与容量边界由单元测试锁定 |
| 敌人太慢 | Hunter 改为追踪/侧切/短冲三态；Striker 加速并成对交叉；Swarm 以 3–5 个单位分翼推进 | 普通生成间隔目标为 `0.72/0.55/0.42` 秒，下限 `0.30` 秒；低生命时仍保留动态喘息预算 |
| 攻击方式单一 | 新增 Lancer 持续光束、Swarm 分翼、Mine 雷墙、Elite 冲击波；Boss 二阶段加入横扫光束、三角脉冲与两侧蜂群 | 高伤攻击统一 telegraph/active/cleanup 生命周期，Boss 低于 50% 进入二阶段，胜利/超时/重开均清理 hazard |

| 画风粗糙 | 重做楔形船体、分离翼、椭圆动力核、三段尾焰；敌人按角色拥有不同轮廓；背景增加三层流体线、雾光和远近层 | 桌面启用 Bloom + OutputPass；移动/窄屏/粗指针/reduced-motion 自动降级，无 Composer 开销 |
| 高密度可能卡顿 | 敌人/粒子/拖尾硬上限，粒子与拖尾池化，热循环复用向量，异常实体和 NaN/Infinity 自动清理 | 单元测试 21/21 通过；生产构建通过；仅保留 Three.js 主包超过 500 kB 的构建提示 |
